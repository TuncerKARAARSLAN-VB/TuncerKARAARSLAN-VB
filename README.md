# The Vebende Akademi Learning Model

## Education Over Decoration

Every program is designed to produce observable and measurable technical progress.

### Live Education

Classes are delivered live, allowing participants to:

* Ask questions
* Discuss architectural alternatives
* Examine real-world scenarios
* Write code with the instructor
* Troubleshoot problems interactively
* Receive immediate technical feedback

### Hands-on Engineering

Programs are generally structured around:

* **30% conceptual foundation**
* **70% hands-on implementation**

Participants do not only learn what a technology is.

They learn how and why it is used in production.

### GitHub-Based Evidence

GitHub is integrated into the education process.

Participants use GitHub to publish and demonstrate:

* Assignments
* Source code
* Documentation
* Architecture decisions
* Infrastructure definitions
* CI/CD pipelines
* Security improvements
* Laboratory exercises
* Capstone projects

> **A CV describes knowledge. GitHub demonstrates capability.**

### Assignments and Projects

Training programs may include:

* Two assignments for each training period
* Technical code reviews
* Public GitHub repositories
* Three capstone project alternatives
* At least one completed capstone project
* Architecture and security documentation
* Automated build and deployment workflows

### Three-Level Badge System

Competency development is supported by a three-level evidence model:

1. **Awareness Badge**
   Demonstrates active participation and conceptual understanding.

2. **Participation Badge**
   Demonstrates assignment completion and continuous technical contribution.

3. **Project Badge**
   Demonstrates the ability to complete and present a production-oriented project.

# Spec-Driven Development

I am developing a comprehensive engineering and education framework around **Spec-Driven Development**.

Artificial intelligence is changing software development, but uncontrolled code generation creates new risks:

* Ambiguous requirements
* Architectural inconsistency
* Security vulnerabilities
* Uncontrolled dependencies
* Missing test coverage
* Weak documentation
* Untraceable decisions
* Production instability

Spec-Driven Development moves software development from informal prompting toward explicit, testable and governed specifications.

## Program Levels

1. **Spec-Driven Development Foundation**
2. **Spec-Driven Development Professional**
3. **Agentic Software Development**
4. **Enterprise Spec-Driven Engineering**
5. **Autonomous Software Factory**

## The Spec Universe Vision

The broader vision includes:

* Specification methodology
* Specification language
* Architecture constraints
* Security requirements
* Testing standards
* Acceptance criteria
* AI agent orchestration
* Code-generation governance
* DevSecOps integration
* Deployment policies
* Observability requirements
* Quality gates
* Auditability
* Training
* Certification

The objective is to establish a disciplined engineering model in which humans and AI agents can collaborate without sacrificing architecture, security or quality.
